# PaperTradingBot

Автономный торговый робот на Python и BackTrader для **виртуальной торговли (paper trading)** по рыночным данным Финама. Проект рассчитан на запуск одного робота с одним независимым виртуальным счётом. В дальнейшем каждый экземпляр робота можно запускать в собственном Docker-контейнере.

> **Безопасность:** Финам используется исключительно как источник котировок. Виртуальные сделки должны исполняться симулятором BackTrader. Подключение реального брокера через `store.getbroker()` или вызовы API размещения заявок в paper-режиме недопустимы.

## Технологии

- **Python 3.12** — среда выполнения.
- **BackTrader** — стратегии, обработка баров и симуляция исполнения.
- **FinLabPy / FinamPy** — подключение к данным Финама.
- **CSV и JSON** — локальное хранение виртуального счёта и результатов торговли.
- **Docker** — запланированный способ развёртывания отдельного робота.

## Подготовка на macOS

1. Сделайте копию исходного проекта `Finam_Data` в Finder и назовите её `PaperTradingBot`.
2. Удалите **только из копии** старую папку `.venv`.
3. Откройте `PaperTradingBot` в VS Code и создайте новое окружение:

   ```bash
   python3.12 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements.txt
   ```

4. Если локальные `FinamPy` / `FinLabPy` не устанавливаются через `requirements.txt`, установите их в соответствии с их `pyproject.toml` или инструкциями проекта.
5. Выберите `.venv/bin/python` через команду **Python: Select Interpreter**.
6. Проверьте абсолютные пути в `.vscode/settings.json`, `.vscode/launch.json` и `.env`: они могли сохраниться от `Finam_Data`.

## Запуск

После переименования `PaperTrading_Finam.py` в `main.py`:

```bash
source .venv/bin/activate
python main.py
```

До запуска проверьте, что в `main.py` используется **локальный симулятор брокера BackTrader**, а не брокер, возвращаемый `FinLabPy` / `FinamPy` для реальных операций. Наличие имени `PaperTrading` в файле само по себе не гарантирует отсутствие реальных заявок.

Работа с live-котировками рассчитана на длительный процесс; для штатной остановки используйте `Ctrl+C`. Корректное закрытие потоков и соединений с Финамом нужно предусмотреть в обработчике завершения.

## Учёт виртуальной торговли

Каждый экземпляр робота ведёт собственную папку `PaperAccount/`.

| Файл | Назначение | Когда обновляется |
| --- | --- | --- |
| `account.json` | ID счёта, начальный капитал, валюта, правила комиссий | При настройке счёта |
| `trades.csv` | Исполненные **виртуальные** покупки и продажи | При каждом исполнении |
| `equity.csv` | Денежный остаток, стоимость открытых позиций и капитал | После обработки завершённого бара |

Рекомендуемые поля:

**`account.json`**

```json
{
  "bot_id": "bot1",
  "currency": "RUB",
  "initial_cash": 1000000,
  "commission_rate": 0.0005
}
```

**`trades.csv`**

```csv
execution_id,timestamp,symbol,side,quantity,price,commission
1,2026-11-16T10:15:00+03:00,SBER,BUY,100,294.50,14.73
```

**`equity.csv`**

```csv
timestamp,cash,positions_value,equity,pnl
2026-11-16T10:15:00+03:00,970535.27,29450.00,999985.27,-14.73
```

Здесь `equity = cash + positions_value`, а `pnl = equity - initial_cash` (при отсутствии пополнений и выводов). Значения приведены **как примеры формата**, а не как результат действующей стратегии.

### Требования к сохранению

- Не записывать одно исполнение дважды: у каждого исполнения должен быть устойчивый `execution_id`.
- Сохранять комиссию и фактическую цену виртуального исполнения.
- Использовать согласованный часовой пояс, предпочтительно время с UTC-смещением.
- Предусмотреть восстановление состояния из истории исполнений после перезапуска.
- Не допускать одновременной записи нескольких процессов в один и тот же CSV.

## Docker и мониторинг — следующие этапы

Планируется схема **один контейнер = один робот = один виртуальный счёт**. Папка `PaperAccount/` должна подключаться к постоянному тому, а `.env` — передаваться отдельно от Docker-образа. Несколько экземпляров робота могут использовать общие рыночные данные, но должны сохранять результаты в разные каталоги.

Отдельный сервис мониторинга в перспективе будет получать heartbeat и технический статус роботов, а из `trades.csv` и `equity.csv` — сделки, динамику капитала и просадки. База данных на первом этапе не требуется.
